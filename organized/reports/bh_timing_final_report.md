# B/Hタイミング可変性 最終分析報告

## 実験パラダイム: Go/No-go課題（Go cueのみ）

### 新仮説の検証結果

## 1. 重要な発見

### タイミング分布の二峰性
- **59.2%の試行**: E→B/H遅延が約1秒（0.9-1.1秒）
- **40.8%の試行**: E→B/H遅延が10-22秒

### 長遅延の正体
**長遅延試行では、EとB/Hの間に別のEイベントが存在**
- これは、記録されたB/Hが実際には次の試行の結果である可能性を示唆

## 2. イベントの真の意味（修正版）

### 実際のイベント配置と意味
```
E (index_B+3): Go cue提示 - 50個
↓ [0-1秒の判定窓]
W (index_B+13): Hit判定結果 - 29個（約1秒後）
H (index_B+6): Miss判定結果 - 21個

B (index_B+0): 別のタイミングマーカー（報酬関連） - 29個
```

### 正しいマッピング（0.5-1.5秒窓）
- Hit: 29試行（すべて約1秒後）
- Miss: 0試行（1秒窓内には存在しない）
- No outcome: 21試行

## 3. 新解釈：二つの異なるプロセス

### プロセス1：Hit試行（約1秒遅延）
1. E（Go cue）提示
2. 判定窓（0-1秒）内でLick検出
3. W（Hit判定）を約1秒後に記録
4. 報酬提示プロセス開始

### プロセス2：Miss試行（長遅延）
1. E（Go cue）提示
2. 判定窓（0-1秒）内でLickなし
3. **次の試行開始まで待機**
4. H（Miss/タイムアウト）は別のタイミングで記録

## 4. B（index_B+0）イベントの役割

### B-W時間差の異常
```
B2: W(50.56秒)の28.53秒前
B3: W(80.10秒)の15.01秒前
B4: W(96.12秒)の31.03秒前
```

**結論**: Bイベントは報酬消費完了ではなく、**前の試行**の何らかのマーカー

## 5. 正しい試行構造

### 実際の試行フロー
```
試行n:
E(n) → [0-1秒判定] → W(n) or タイムアウト
        ↓
      ITI（約15秒）
        ↓
試行n+1:
E(n+1) → [0-1秒判定] → W(n+1) or タイムアウト
```

### Miss試行の記録問題
- Miss判定は即座に記録されない
- Hイベントは試行間のタイムアウトマーカーの可能性

## 6. コード修正への影響

### 現在のコードの問題
```matlab
% 誤った仮定
Hit_Go_cue = Hit_cue - CS_time;  % Wから1秒引く
Miss_Go_cue = miss_cue - CS_time; % Hから1秒引く
```

### 正しいアプローチ
```matlab
% E（Go cue）を直接使用
Go_cue = event1;  % index_B+3のイベント

% Hit試行のみ正しくマッピングされる
% Miss試行は別途処理が必要
```

## 7. 最終結論

### 主要な知見
1. **Hit試行は正しく約1秒後に記録される**
2. **Miss試行のHイベントは試行と直接対応していない**
3. **長遅延は試行間マッピングの誤り**
4. **Bイベントは報酬消費ではなく別のプロセス**

### 実験設計の推定
- Go cue後0-1秒が判定窓
- Hit: 判定窓内にLick → 約1秒後にW記録
- Miss: 判定窓内にLickなし → 別のタイミングでH記録
- ITI: 約15秒（11-21秒の範囲）

### データ処理への提言
1. **E（Go cue）を基準時刻として使用**
2. **W（Hit）は約1秒後のマッピングで正しい**
3. **H（Miss）は試行対応の再検討が必要**
4. **長遅延データは除外または特別処理**
