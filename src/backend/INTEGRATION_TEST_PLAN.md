# 統合テスト計画書

## 概要
dev3のシステム統合完了後に実施する統合テストの計画書

## テスト環境
- **APIサーバー**: FastAPI (http://localhost:8000)
- **データベース**: SQLite (開発環境)
- **Python**: 3.8以上
- **依存ライブラリ**: requirements.txt参照

## 統合テストシナリオ

### 1. エンドツーエンド患者フロー
1. 新規患者登録
2. 各種データアップロード（写真、レントゲン、模型）
3. 咬合分析実行（dev3）
4. 治療計画生成
5. 治療シミュレーション
6. レポート生成

### 2. データ整合性テスト
- [ ] 患者データのCRUD操作
- [ ] ファイルアップロードと参照
- [ ] 分析結果の保存と取得
- [ ] 治療計画の永続化

### 3. API連携テスト
- [ ] 咬合分析エンジン → 治療計画生成
- [ ] 画像データ → 分析エンジン
- [ ] 統合分析 → レポート生成

### 4. パフォーマンステスト
- [ ] 100患者同時アクセス
- [ ] 大容量ファイルアップロード（10MB以上）
- [ ] 複雑な治療計画生成（レスポンス時間測定）

### 5. エラーハンドリングテスト
- [ ] 不正なデータ形式
- [ ] 存在しない患者ID
- [ ] ファイルアップロード失敗
- [ ] 分析エンジンタイムアウト

## 実行手順

### 1. 環境準備
```bash
cd /mnt/d/multiagent-system/src/backend
source venv/bin/activate
pip install -r requirements.txt
```

### 2. APIサーバー起動
```bash
./start_backend.sh
```

### 3. エンドポイント確認
```bash
python verify_endpoints.py
```

### 4. 統合テスト実行（dev3完了後）
```bash
python run_integration_tests.py
```

## 成功基準

### 機能要件
- 全エンドポイントが正常に動作
- データの一貫性が保たれる
- 分析結果が正確に生成される
- 治療計画が妥当な内容で生成される

### 非機能要件
- APIレスポンス時間: 90%が3秒以内
- ファイルアップロード: 20MBまで処理可能
- 同時接続数: 100接続まで安定動作
- エラー率: 1%未満

## リスクと対策

### リスク1: dev3統合の遅延
- **対策**: モックデータで基本テストを先行実施

### リスク2: パフォーマンス問題
- **対策**: プロファイリングツールで事前分析

### リスク3: データ不整合
- **対策**: トランザクション処理の実装確認
